# 就诊记录模块 · 设计方案

> 本文档是"计划"阶段的产物：先用四要素提示词让 AI 出方案，人工确认后才动手写代码。
> 记录在此，作为工作流第 ② 步（计划）与第 ③ 步（实现）之间的凭证。

## 一、需求（四要素）

- **角色**：熟悉医院门诊业务的前端工程师
- **目标**：实现"就诊记录"列表页与详情页
  - 列表：就诊号、患者姓名、科室、诊断、就诊时间、状态，点击进入详情
  - 详情：患者基本信息、就诊信息、处方摘要
- **约束**：纯 HTML + CSS + 原生 JS，零第三方依赖；数据来自静态 `data/visits.json`；
  患者数据必须虚构；`npm run dev` 能用 Node 内置模块起服务
- **格式**：先给页面结构、字段与路由方案，确认后再写代码

## 二、页面与路由

| 页面 | 文件 | 入参 | 说明 |
| --- | --- | --- | --- |
| 列表页 | `index.html` | 无 | 渲染全部就诊记录，行末「查看」跳详情 |
| 详情页 | `visit.html` | `?id=V001` | 按 id 从同一份 JSON 中查找并渲染 |

> 采用两个静态页面 + 查询参数，而不是前端路由：零依赖、双击也能打开，
> 与实验一"零构建预览"的思路一致。

## 三、数据结构

`data/visits.json` 为数组，单条记录字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键，详情页查询用（V001…） |
| `visit_no` | string | 就诊号（对患者展示） |
| `patient_name` | string | 患者姓名 |
| `gender` / `age` | string / number | 性别、年龄 |
| `department` | string | 科室 |
| `doctor` | string | 接诊医生 |
| `diagnosis` | string | 诊断结论 |
| `visit_time` | string | ISO 8601 时间 |
| `status` | string | 已就诊 / 待就诊 / 已取消 |
| `fee` | number | 本次费用（元） |
| `chief_complaint` | string | 主诉 |
| `prescription` | array | 处方明细：药名 / 规格 / 用法用量 |
| `note` | string | 医嘱 |

## 四、实现要点

1. **列表渲染**：`fetch` 取 JSON → 逐行拼接 `<tr>`；空数据与加载失败各有占位文案。
2. **安全**：所有插入 DOM 的字段经 `esc()` 转义，防止数据里的尖括号破坏结构。
3. **时间格式**：JSON 存 ISO 8601，展示为 `YYYY-MM-DD HH:mm`。
4. **状态样式**：`已就诊 / 待就诊 / 已取消` 三色 pill，用 CSS class 控制。
5. **错误处理**：缺少 `?id=`、id 不存在、HTTP 失败，分别给出可读提示而不是白屏。
6. **响应式**：窄屏下详情两栏变一栏，列表隐藏"就诊时间"列。
